# HideBar: как устроено

Технические заметки для разработки. Описание приложения — в [README](../README.md).

## Почему Hidden Bar ломал клик по часам

Hidden Bar 1.11 на macOS 27 прячет иконки через приватный `MenuBarClientCore` (`MBAssessmentModeAssertion`). Это ограничение видимости из режима экзамена. В системном логе видно, как оно включается при каждом скрытии:

```
Hidden Bar  [com.apple.menubar:visibility-restriction-xpc-client] VisibilityRestrictionAssertion session activated
```

Пока ограничение активно, Control Center не передаёт клик по часам в Центр уведомлений. Строка `[com.apple.controlcenter:clock] Sending mouse down event to Notification Center` в логе не появляется ни разу, а сразу после снятия ограничения появляется.

## Как HideBar прячет иконки

На macOS 27 строку меню рисует `MenuBarAgent`, и у него есть своё переполнение: то, что не помещается, уходит за системную кнопку «. Старый трюк «растянуть разделитель на 10 000 pt» здесь не работает: слишком широкий элемент система просто убирает в переполнение целиком.

Поэтому HideBar подгоняет ширину пустого элемента-разделителя `|` так, чтобы он занял ровно свободное место между вырезом и иконками справа. Тогда всё, что левее `|`, система сама убирает в переполнение. Своей стрелки у HideBar нет: стрелка в строке меню одна, системная.

- **Запас у выреза** подобран так, что « не помещается левее разделителя, и система рисует её поверх его правого края, вплотную к видимым иконкам.
- **Подгонка.** Ширина сначала берётся максимальной. Если разделитель не помещается (например, рядом системная «пилюля» записи экрана), он ужимается шагами по 24 pt. HideBar подписан на перемещение окна разделителя и замечает это сразу. Если сдвинулась опорная точка (справа появились или пропали иконки), опора перемеряется. Если не помещается ничего, повторная попытка будет не раньше чем через 30 с, чтобы иконки не мигали.
- **Экраны без выреза.** Свободная ширина зависит от меню активного приложения, поэтому она находится бисекцией и кэшируется по приложению.
- **Старые macOS** без `MenuBarAgent` используют классическую схему: стрелка HideBar плюс разделитель на 10 000 pt.

### Открыт ли системный ряд

macOS по клику на « показывает скрытые иконки отдельным рядом слева, после меню программы. Узнать об этом напрямую нельзя, поэтому HideBar держит невидимый элемент-«датчик» левее всех иконок: он всегда лежит в переполнении, а его окно становится «видимым» (`occlusionState`) ровно тогда, когда ряд открыт. Разрешения для этого не нужны.

Когда ряд открывается, HideBar раскрывает иконки на месте: сжимает разделитель до видимой полоски `|`, иконки встают справа от выреза, а не поместившиеся система ставит вплотную к вырезу слева. Когда ряд закрывают кнопкой », всё снова прячется. Пока ряд открыт, ни горячая клавиша, ни клик по `|` не сворачивают иконки, иначе они улетели бы в этот ряд: сворачивание откладывается до ».

### Автоскрытие через Accessibility

Через заданное время (по умолчанию 10 с), когда курсор не в строке меню и не открыто ничьё меню, HideBar сам нажимает ». Это кнопка `MenuBarAgent` с идентификатором `menu-bar-overflow-indicator-expanded` (в закрытом состоянии `menu-bar-overflow-indicator`). HideBar нажимает только кнопку в открытом состоянии, а `AXPress` работает без движения курсора.

### Известное ограничение

Когда «пилюля» записи экрана исчезает, освободившееся место может занять одна спрятанная иконка до следующего клика по «/». Каждое скрытие начинает подгонку с максимальной ширины, так что это выправляется само.

## Отладка

`hidebar://debug` пишет геометрию разделителя и датчика в системный лог, туда же пишутся все решения по раскладке:

```bash
/usr/bin/log show --last 5m --predicate 'subsystem == "dev.qweb.HideBar"'
```

В zsh `log` — встроенная команда, поэтому нужен полный путь `/usr/bin/log`.

## Сборка

```bash
./build.sh            # build/HideBar.app, universal; подпись Developer ID из связки ключей (или ad-hoc)
./build.sh install    # плюс копия в /Applications
swift scripts/make-icon.swift   # перегенерировать Resources/AppIcon.icns
```

Нужен Xcode со Swift 6 и macOS 14+. С подписью Developer ID macOS запоминает разрешение «Универсальный доступ» между пересборками.

## Релизы

`./release.sh 1.0.1` выпускает версию на GitHub:
1. поднимает версию в `Resources/Info.plist`;
2. собирает приложение с подписью Developer ID и временной меткой Apple;
3. упаковывает его в `build/HideBar-1.0.1.dmg` (внутри приложение и ярлык «Программы»);
4. нотаризует и «прошивает» DMG, так что Gatekeeper открывает его без предупреждений;
5. коммитит версию, ставит тег `v1.0.1`, отправляет на GitHub и создаёт релиз с DMG и автоматическими заметками (свои добавляются через `NOTES_FILE=notes.md`).

Перед первым релизом один раз сохрани учётные данные для нотаризации. Пароль приложения создаётся на appleid.apple.com:

```bash
xcrun notarytool store-credentials hidebar-notary --apple-id you@example.com --team-id 2U5V9VG262
```

Проверить всё, кроме публикации: `./release.sh 1.0.1 --dry-run` (с нотаризацией) или `./release.sh 1.0.1 --dry-run --skip-notarize` (без неё). Пробный прогон ничего не коммитит и возвращает `Info.plist` как был.
